## Project portability findings (code inspection)

getCurrentSessionData embeds the current audioBuffer as WAV and includes customNodeBundle, customNodeZipBase64 where available, node parameters, EQ, gain, positions, mute/solo, motion path/speed and master volume.

It does NOT serialize playlist files, playlist order/index or shuffle. Full folder-playlist portability is therefore not implemented. Live input flags are saved but this restore path does not reconnect a live device. External streams remain external; their future audio cannot be embedded as a live source. Instrument internal state beyond params (for example a custom sample buffer or random generator state) is not generally captured by this host serializer.

Serialization failure for a sample is only logged and can still produce a save without embedded sample data. Project loading can finish with a success toast despite individual source errors. applySession stops current playback before substantial validation. Native saving writes directly to its destination. These are review targets, not observed crashes or proven data loss.
